= ISO/TC 204 ITS Vocabulary

https://glossarist.org[Glossarist] concept database for ISO/TC 204, implementing the
https://github.com/glossarist/concept-model[Glossarist Concept Model] (ISO 10241-1
compliant) as a multi-edition **lineage series**.

Live site: https://isotc204.geolexica.org

== Overview

This repository contains terminology data for the ISO/TC 204 Intelligent Transport
Systems vocabulary (ISO 14812). It hosts three editions as sibling datasets under
`datasets/`, with cross-edition `supersedes` relationships wiring them into a
navigable timeline.

== Concept file format

Each `concepts/<id>.yaml` is a multi-document YAML stream:

. **First doc** — `ManagedConcept`: `data.identifier`, `data.localized_concepts`,
  `data.domains`, top-level `related[]`, `status`, `date_accepted`,
  `schema_version: '3'`, `id`.
. **Subsequent docs** — one `LocalizedConcept` per language: `data.terms[]`,
  `data.definition[]`, `data.examples[]`, `data.notes[]`, `data.sources[]`,
  `language_code`, `entry_status`, `id`.

Cross-references inside content use `{{urn:iso:std:iso:14812:<clause>,<display>}}`.
Figure xrefs use AsciiDoc `<<fig-id>>` targeting `figures/<id>.yaml`.

=== Cross-edition `supersedes`

Forward direction only (new → old), authored in the newer concept:

[source,yaml]
----
related:
  - type: supersedes
    ref:
      source: urn:iso:std:iso:ts:14812:2022
      id: '3.5.8.8'
----

The concept-browser derives `superseded_by` at render time. Authoring both
directions is duplication.

== The converter (`Iso14812Import`)

E2 and E3 are produced by the converter under `lib/iso14812_import/`. Re-running
is idempotent — deterministic UUIDv5 from `(edition.urn, clause)` plus framework
serialization gives byte-identical output across runs.

=== Architecture (14 classes, autoload-only)

* `Document` IR (Struct) — parser-neutral intermediate
* `Parsers::XmlParser` (E2), `Parsers::MarkdownParser` (E3),
  `Parsers::YamlDirParser` (loads existing YAML for supersedes lookup)
* `ContentConverter` — coradoc-driven HTML/Markdown → AsciiDoc with inline URN
  cross-reference resolution
* `RelationshipMapper` — source predicate → v3 relationship type
* `FigureRegistry`, `SourceParser`, `ConceptBuilder`, `Writer`,
  `SupersedesDeriver`, `BibliographyBuilder`, `Pipeline`, `PipelineSummary`,
  `DeterministicUuid`

Open/closed: adding E4 = new parser file + edition config. No edits to
`ConceptBuilder`, `Writer`, `Pipeline`, or `SupersedesDeriver`.

=== Common commands

[source,sh]
----
bundle install                                        # set up converter deps
bundle exec rake validate                             # glossarist validate on every dataset
bundle exec rspec                                     # converter test suite (no doubles)
bundle exec ruby -Ilib scripts/import_iso14812.rb \
  --edition config/editions/isotc204-2025.yml \
  --previous config/editions/isotc204-2022.yml        # re-run an import (idempotent)

gem install glossarist                                # if not using bundler
glossarist validate datasets/isotc204-2022/           # validate one dataset
glossarist package datasets/isotc204-2022/ -o out.gcr \
  --shortname isotc204-2022 --version 1.0.0           # build a GCR
----

== Editing concepts

=== Using Glossarist Desktop

Open this repository in the https://glossarist.org/desktop[Glossarist Desktop]
application. The app reads and writes YAML files directly.

=== Manual editing

Each concept file can be edited in any text editor. Key fields:

* `data.terms[].designation` — the term/designation text
* `data.definition[].content` — the definition text
* `data.examples[].content` — example sentences
* `data.notes[].content` — notes
* `data.sources[]` — bibliographic sources
* `status` — `valid`, `superseded`, or `withdrawn`

== Browsing with Concept Browser

This data is built and deployed using
https://github.com/glossarist/concept-browser[`@glossarist/concept-browser`].

The deployment configuration lives in
https://github.com/geolexica/isotc204.geolexica.org[`geolexica/isotc204.geolexica.org`].

== Data pipeline

[source]
----
glossary YAML (this repo, per edition)
  → GCR package (one GitHub Release .gcr per edition)
    → concept-browser build (fetch + generate + vite build)
      → GitHub Pages deployment (isotc204.geolexica.org)
----

GCR packages are built automatically by the `publish-gcr` workflow on push to
`v*` tags. One package per edition, with unversioned aliases for "latest of
this edition".
